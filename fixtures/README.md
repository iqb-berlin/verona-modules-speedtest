# Layout fixtures

Self-made units for checking the player layout by hand. They contain no real test content, so they can live in the repo. Generated by [`scripts/make-fixtures.mjs`](../scripts/make-fixtures.mjs) — change the script and rerun it instead of editing the JSON:

```bash
node scripts/make-fixtures.mjs
```

## What is here

- `{layout}_{questionType}_{answerType}.json` — one unit per format combination the editor allows (2 layouts × 3 question types × 4 answer types), plus `word-select.json` and `inline-answers.json`. All have an instruction text.
- `variant_*.json` — unit-level settings that change the layout: without instruction text, multiple selection, question space ratio 30 and 70, fixed button width 350px.

Each unit's items pair every question case with the hardest answer case (4 long answers, 4 mixed-format images, 4 labelled audio answers, 6 digits), and every answer case with a plain question. 4 answers is taken as the realistic maximum.

Images are SVGs at an exact pixel size with that size written on them; the circle shows if an image is distorted. Audio is a short generated tone.

## Checking

Start the player (`npm run start-player`), load a fixture with "Unit laden" and click through all items, in iPad landscape (1024×768) and portrait (768×1024) — the browser's device mode is enough. On every item look for anything cut off, overflowing or badly scaled. Note that `.inner-wrapper` clips its content (`overflow: hidden`), so cut-off content does not show as scrolling: look at the edges of the question and answer areas, not only the screen edges.
